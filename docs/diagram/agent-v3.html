Agent Loop = turn / step 生命周期 —— 完整过程(不止 ReAct)
① 接单:开回合,收下消息和排队输入
② 备料:拼上下文,列出可用工具
③ 准入闸 = agent/pre-step(系统判断):改"进模型的对话消息",或拦掉 —— 独立于 ReAct
④ 干活:进入 ReAct 循环(右);"再来一轮"的判断就在循环里
⑤ 落账:关回合,全程记录;外部可随时叫停
dsh 术语:①turn/start · ③agent/pre-step · ⑤turn/end · turn-stopping=外部叫停

黄金法则:SQLite = 事实源 · Qdrant = 可重建的派生索引 · Redis = 可丢失的加速层 —— 易失层全空,系统照常跑
SQLite 事实源
  • 会话日志 · 审计 · token 账本
  • 原文快照 + 历史版本(引用寻址)
  • WAL · append-only · 单写者
  • schema 版本 fail-closed
使用者:④ ⑥ ⑨
Qdrant 派生索引
  • 知识向量 · 稠密 + 稀疏混合
  • 只索引当前生效版本
  • payload:产品/版本/生效日期/来源
  • 换嵌入模型 = 全量重建
使用者:⑧(可从 SQLite 重建)
Redis 易失加速
  • 嵌入缓存 · 幂等工具缓存(TTL)
  • 限流 / token 预算 · 锁与热态
  • 不缓存 LLM 补全与被依赖的读
  • 单进程阶段无需 pub/sub
使用者:② ③ ⑦(清空即恢复)
四条铁律
① 模型可见 ⇔ 已记录:检索片段+引用+回答全落 SQLite,历史角标永远可点  |  ② 易失层可随时清空:Redis / Qdrant 全空照常跑;事实源只有 SQLite
③ 回答必须可追溯:不确定就拒答转人工;引用绑定版本,条款更新不失效  |  ④ 上限加在完整结果上:步数 / token / 字节 + 每客服 token 预算
