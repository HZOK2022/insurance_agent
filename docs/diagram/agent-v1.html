编排核心：core/agent（ctx.agents 生命周期 + 注册表）· core/agent-loop（ctx.agentLoop 默认驱动）· core/scope（每 agent 作用域注册）

dsh 无独立检索模块,故这里只有"输入消息改写"(agent/pre-step);"检索查询改写"属你们的 v2/v3 的 ⑧ 知识检索
这里的 "step：模型请求 ↔ 工具调用" 就是 ReAct —— 思考(模型请求)→ 行动(工具调用)→ 观察(结果回填)→ 再思考;工具欠结果 / 有新消息就再来一轮,都不欠就收敛输出回答

  • append-only 事件日志 = 唯一事实源
  • 持久化 JSONL/SQLite · 投影 · fork · compaction

四条核心铁律
① 模型可见 ⇔ 已记录：进入模型请求的内容必须能从日志重建，新输入 ⇒ 新会话事件  |  ② 扩展点优先：新行为挂事件 / seam / profile，不改 agent-loop
③ 瀑布监听必须 next()：不调用即短路整条链  |  ④ 大声失败：误配置在加载或最早可解析点报错，绝不静默跳过；注册即 effect，返回 disposer
